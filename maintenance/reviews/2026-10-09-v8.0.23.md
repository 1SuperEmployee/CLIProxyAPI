# Upstream review: v8.0.16 to v8.0.23

Decision: retain the accepted `8.0.16-se-affinity.4-rc1` executable while qualifying
`v8.0.23` separately. Its fixes justify qualification; source tests alone do not
justify replacing a live service. No service, login, route or runtime setting changed.

## Fork compatibility and checks

Upstream does not edit our selector, session cache, durable checkpoint files or
`service_config.go` persistence wiring. Durable affinity remains our patch, not an
upstream feature. Binding validity/eligibility/TTL/failover remain separate from cache hits.

One merge conflict: `service_catalogs_test.go`. Our earlier Home-mode cleanup
backport overlaps upstream `da5f109f`, which also restores every fixture catalog
path. The candidate uses upstream's full test cleanup. No production conflict
was manually resolved and no production workaround added.

`internal/usage`, `sdk/usage` and `internal/redisqueue` have no diff across these tags;
this supports recorder source compatibility, not candidate runtime acceptance.

## Open reports and proposals

- [6491: null cache marks](https://github.com/router-for-me/CLIProxyAPI/issues/6491):
  reproduced offline. One valid ephemeral mark plus five `cache_control: null`
  message blocks are counted as six; enforcement at four removes the valid mark.
  This logic predates the update. Whether this fleet's native Claude Code emits
  that payload is unproved. Track the upstream fix and qualify affected payloads;
  no downstream fix added here.
- [6469: incomplete Codex streams](https://github.com/router-for-me/CLIProxyAPI/issues/6469):
  operator report, not a defect established in this fleet or a proven timeout.
  Latest release was not reproduced in that report. Correlate evidence if seen;
  do not add blanket retries or timeouts.
- [6485: reasoning generation timing](https://github.com/router-for-me/CLIProxyAPI/issues/6485):
  proposal, not shipped. `output_tokens / (latency - ttft)` cannot establish real
  generation speed on reasoning models.
- [2998: strict Codex WebSocket affinity](https://github.com/router-for-me/CLIProxyAPI/pull/2998):
  open proposal. Cross-account failover can invalidate opaque `previous_response_id`.
  Our account/restart proof does not establish opaque continuation failover.
- [6172: quota-aware Claude routing](https://github.com/router-for-me/CLIProxyAPI/pull/6172):
  open alternative launcher/design. Its self-contained versus opaque-history
  distinction is useful; importing the architecture is not necessary for a reset
  preference. Healthy existing bindings still win.
- [4509: affinity statistics](https://github.com/router-for-me/CLIProxyAPI/pull/4509):
  open proposal on deprecated `/v0/management`, not an available diagnostic or an
  upgrade dependency. Our enrollment check also uses a legacy management endpoint;
  operator migration needs a separately tested change.
