# Upstream main review, 10 October

## Decision and source

Latest stable at review is v8.0.23. Review target is unreleased main commit
`3de4e248f6bb12fc7dfafb183404f3b248578922`, eight non-merge commits newer
than stable. Candidate branch `se/review-main-2026-10-10` merges this exact head
into maintained source, merge commit `afeb3f50`. This is source integration only,
not accepted software or a deployment. No live gateway or credential change.

The maintained branch still carries the older accepted source with documentation
of the separately deployed v8.0.23 candidate. Consequently this merge also includes
the previously reviewed v8.0.16-to-v8.0.23 changes. Comparing the candidate tree
with `se/review-v8.0.23` leaves exactly the27 files changed since v8.0.23.
The catalog-test conflict was resolved to the identical upstream/current-v23 test,
which already carries the needed Home-mode cleanup. No new test workaround.

## Relevant changes

- `be8c35f2`: valid Claude cache marks alone count toward limits and control
  injection/TTL normalization. Null and invalid marks cannot displace valid ones.
  Watched issue6491 is now closed. Upstream adds regressions for invalid/null
  marks. This addresses our previous offline reproduction; no new live cache-hit
  improvement is claimed.
- `5dbd92a0`: preserve upstream-confirmed RetryAfter cooldown when cancellation
  races error delivery, and notify WebSocket disconnection after delivering its
  cause. Plain client cancellation without RetryAfter is not a provider cooldown.
  Reviewed bootstrap preference, cancellation-independent result recording and
  nil-safe disconnect notifier. Real failover/recovery remains an acceptance gate.
- `b0debb35`: deterministic bounded Codex call IDs for chat-completions translation,
  including duplicate-ID handling and matching pending tool results. Our native
  Responses clients are a different route; do not claim this fixes every native
  tool continuation.
- `37fe2608`: client-authentication provider and native-key metadata propagate to
  usage records and plugins. The raw upstream usage record can carry an API key.
  Our recorder uses a strict field allowlist; a synthetic compatibility check
  verified api_key, access_provider and is_native_key are discarded and a supplied
  synthetic key is absent from the stored record. No schema or collection change
  is needed for this update. Raw queues/plugin payloads must remain private.
- `cad1b503` corrects Devin streamed token estimates; `dfe0a0ef` removes spurious
  Antigravity tool-call deltas. Two README commits change project/sponsor listings.

## Custom patch and compatibility

The durable selector, schema-1 checkpoint implementation and service persistence
configuration are byte-identical to the prior v8.0.23 candidate. No provider auth
file migration was introduced by these eight commits. The recorder ignores added
fields, rather than automatically persisting them. Affinity, provider caching and
usage collection remain separate mechanisms.
