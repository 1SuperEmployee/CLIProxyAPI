# Stable v8.0.42 security and compatibility candidate

## Decision

Candidate production code `db965301` merges official stable `v8.0.42`,
`bc0643405a1d0adf77dd0f109972ac3313d66397`, into the accepted v8.0.35 fork.
This is a qualification record, not deployment acceptance. The accepted executable
and recovery instructions in CURRENT.md remain authoritative until cutover.

Use Go 1.27.3 for this artifact. The old accepted compiler, Go 1.27.1, lacks
subsequent HTTP/TLS and certificate-trust security fixes. The upstream dependency
updates include x/net 0.60.0, x/text 0.42.0, x/crypto 0.57.0 and go-git alpha.5.
Additionally update klauspost/compress from 1.17.4 to 1.18.7, addressing
GO-2026-5841. Do not infer security from the application version string alone.

## Relevant released changes

- Request-log filename sanitization and path containment, including forced
  error logging when ordinary request logging is disabled.
- Credential header removal on plugin HTTP redirects to a different origin.
- Runtime cooldown retention during credential file scans, re-read of discarded
  snapshots, preservation of credentials when scans fail, refresh/token fencing
  and synchronized management config reads during OAuth operations.
- Native Claude Agent SDK caller recognition, account-scoped web-search caching,
  empty text/tool schema handling, context-limit/refusal stop reasons and deferred
  search continuations.
- Codex guardian parent-account preference, native credential/search routing,
  explicit parallel-tool-call false, effort and usage/metadata handling.
- Reduced repeated per-stream tool metadata work. No measured whole-agent speedup
  is claimed from these source changes.

Optional cluster/Home, SIWC, provider and WebSocket features are not activated.
This update changes no production model, effort, permission, login or quota policy.

## Fork reconciliation

Retain durable schema-1 account affinity, bounded nearest-reset selection,
optional ledger read bridge, config ordering/SourceHash, strict native SSE/compaction
corrections and both credential snapshot fences.

The lifecycle conflict must recognize file snapshots in both replace mode and the
fork's snapshot mode. Upstream's cooldown preservation applies to both.
The session cache conflict must retain persistence dirty markers and cold-pick
locks as well as upstream's session-group index and selection sequence.
Restore schema-1 bindings with an empty volatile selection binding; do not silently
change the checkpoint format or make the accepted rollback unable to decode it.

The first full-suite run caught `TestHandleAuthUpdatesDiscardedSnapshotTriggersWatcherReread`.
Our observation-fence early return skipped upstream's new watcher re-read.
The fix invokes that re-read for a rejected bound file snapshot before returning.
The original regression now passes. A new integration regression verifies that a
restored parent retains its account and repopulates guardian selection metadata
before a new guardian review. No new production routing mechanism was added.

Guardian newest-parent selection metadata is intentionally not in schema1.
A new guardian request arriving immediately after process restart and before a
parent request cannot consult a restored newest-parent index. Existing child and
parent account bindings remain durable. This limit must not be described as full
durable guardian inheritance.

## Qualification

- macOS Go1.27.3: full suite, 102 packages with tests, passed.
- macOS relevant race checks: auth, service, watcher, config, logging, plugin host,
  executor, management and Claude handler passed across the two recorded runs.
- Merge-boundary snapshot/durable-parent regressions passed three repetitions.
- Source `govulncheck`1.9.0 with Go1.27.3: no vulnerable called symbols. The only
  remaining finding is module-level GO-2026-5932 concerning unmaintained OpenPGP;
  the flagged OpenPGP package is not imported/called by this application.
- Server compilation passed on macOS.
- Linux full/race and Windows CGO artifact/filesystem/startup qualification are
  in progress. Do not treat this record as clearance for deployment yet.

The first Linux container attempt mounted source read-only. An upstream test
creates a temporary directory relative to its package, so it failed with EROFS.
Qualification was rerun using the disposable writable extracted source. The test
was not removed, skipped or changed to conceal that environment error.

Synthetic tests use empty auth and temporary state. Never qualify a candidate by
running it against live provider credentials or the live routing checkpoint.
The accepted artifact must remain byte-for-byte retained for recovery.

## Open upstream proposals

Reviewed PR6960, which addresses WebSocket deferred logging retention, PR6968,
which isolates account-entry JSON failures, and PR6954, which adds multi-replica
consistent hashing. They are open and not included in stable v8.0.42. Native
HTTP/SSE clients do not establish an affected WebSocket path. A single durable
credential-owning gateway does not require multi-replica hashing. Do not install
unmerged proposals merely because their titles sound relevant.

## Recovery and acceptance boundary

Use a new checksum-pinned v13/v12 executable transition after artifact qualification.
Preserve current OAuth files, schema1 checkpoint, console, service environment and
all native conversations. Update a stale maintenance roster before using it with
a changed client fleet. Coordinate an idle boundary, then verify actual retained
conversations and account/cache attribution after cutover. Source tests and a
healthy HTTP listener are not proof of those real-client outcomes.
